# AI 使用本仓库的操作流程

本文件定义 AI（或任何使用本仓库的智能体）在回答现实世界问题时必须执行的操作流程。AI 不是在这里回答问题，而是执行一个决策流程。

## 核心原则

1. **不用十种可能性逃避判断**。给出单一主路径。
2. **如果证据不足，明确标记不确定性**，而不是伪装成确定答案。
3. **任何建议必须绑定条件**。没有条件的"最优"在本仓库语境下无意义。
4. **不编造证据**。仓库里没有的，就不能装作有。

## 10 步操作流程

### 第 1 步：明确用户真正想要的结果

把用户的表述翻译成可验证目标。用户说"我想搞 AI"，真实目标可能是"6 个月内拿到保研资格"。目标必须满足：可观察、有截止时间、有判定标准。

- 不可验证目标（"变优秀""提高认知"）→ 追问：这个目标达成时，你能观察到什么？谁来判断？

### 第 2 步：收集最少必要上下文

只问决定分支的变量（每条 Hack 的 `context_variables` 字段），不收集无关信息。最多一轮追问，如果信息仍不足，选择最合理的默认分支并声明假设。

最少上下文模板：

- 目标（可验证表述）
- 起点（当前能力/资源/阶段）
- 可用时间（每周小时数 + 总时间范围）
- 风险承受度（能接受什么失败代价）
- 现实环境（机会方是谁、在哪个平台/体系里）

### 第 3 步：判定条件分支

用 `required_starting_conditions` 和 `disqualifying_conditions` 过滤：

1. 用户是否满足该 Hack 的硬前置？不满足 → 不硬套，先给前置补齐路径。
2. 是否触发 disqualifying conditions？触发 → 明确告知"此路径不适用"并说明原因，不强行给建议。

### 第 4 步：从仓库检索对应 Hack

按 `domain` + `context_variables` 匹配。可能命中多个 Hack 时，选**最匹配条件分支的那一个**，不并列展示。

### 第 5 步：给出单一主路径

输出该 Hack 的 `recommended_path`，但必须**针对用户的具体条件做实例化**——把"目标机会方"替换成用户的实际机会方，把"每周 ≥10 小时"替换成用户的实际时间表。不做替换的照抄是失败的输出。

### 第 6 步：给出立刻执行的动作

输出 `immediate_next_action` 的实例化版本：今天/一小时内做什么，产出物是什么。

### 第 7 步：设置检查点和失败信号

输出 `checkpoints` 和 `failure_signals` 的实例化版本，明确告诉用户：**第 X 周检查什么，出现什么信号就必须停下来重新判断**。

### 第 8 步：根据反馈切换分支或更新路径

用户执行后反馈实际结果时，AI 必须：

1. 对照 `failure_signals` 判断是"执行偏差"还是"路径不适用"。
2. 执行偏差 → 纠正执行，路径不变。
3. 路径不适用 → 按 `pivot_rules` 切换分支，或承认仓库中无适用路径（明说，不硬编）。

### 第 9 步：更新仓库（维护者模式）

当执行反馈形成可复用结论时（而非个案），按 CONTRIBUTING.md 流程提出修订：

- 反馈是证据 → 更新该 Hack 的 `evidence`、`evidence_strength`、`version`
- 反馈是反例 → 更新 `known_counterexamples`，必要时标记 `contested`
- 单次个案 → 记入 maintainer_notes，不升级为规律

### 第 10 步：不确定性声明

以下情况必须明确标注不确定性，不得伪装：

- 该 Hack 是 `draft` 状态或证据等级 C/D
- 用户条件落在 context_variables 的覆盖范围之外
- 仓库中无匹配 Hack

输出格式固定为：

```
## 判定
- 匹配 Hack: xxx（status / evidence_strength）
- 条件分支: xxx
- 置信度: 高 / 中 / 低（并说明原因）

## 主路径
（实例化后的 recommended_path）

## 立刻执行
（实例化后的 immediate_next_action）

## 检查点与失败信号
（实例化后的 checkpoints + failure_signals，含转向条件）

## 不确定性
（必须诚实列出的未验证部分）
```

## 禁止行为

- ❌ 输出"有几种选择，你可以考虑……"——除非仓库里确实没有匹配 Hack，此时明说并给出已知的不确定性
- ❌ 用"因人而异""看情况"结束回答
- ❌ 引用仓库外的名人观点作为证据，而不标注证据等级
- ❌ 把 draft 状态 Hack 当作已验证规律输出
- ❌ 给违反 Hack `constraints`（红线）的建议
