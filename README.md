# Society Hack

> **A versioned repository of high-probability paths to real-world outcomes under explicit conditions.**
> 在明确目标、约束条件、时间和社会环境之后，定义当前高胜率行动路径的版本化知识仓库。

---

## 这是什么

大语言模型能给出平均正确的、教科书式的、各方都不得罪的建议。但它无法把每一个真实社会环境、每一种处境、每一种拿结果的方法完整压缩进参数里。

本仓库做的事情：把**特定条件下高胜率拿结果的路径**整理成版本化、可验证、可反驳的知识条目（Hack），让 AI 在拿到用户上下文后，检索对应分支，给出**单一主路径 + 立刻可执行的动作 + 检查点 + 失败信号**，而不是把十个选项重新丢给用户。

它不是百科全书、不是人生鸡汤、不是教程合集、不是观点陈列场、不是最佳实践链接目录。

## Conditional Optimum：本仓库对"最优"的严格定义

"最优路径" = 在**特定目标 T、起点 S、可用资源 R、时间范围 H、风险承受度 A、现实环境 E** 之下，预期成功率、速度、成本、杠杆综合更优的行动序列。

它从来不是无条件、跨时代、跨人群的宇宙真理。修改任何一个变量，最优路径都可能改变。

| 错误示范 | 正确示范 |
|---|---|
| "所有本科生学习 AI 的唯一正确方法" | "一个希望在 6-12 个月内获得 AI 科研成果、具备基本编程能力、可投入固定时间、目标是进入更强课题组或申请研究机会的本科生，当前高胜率路径" |
| "想搞钱就应该做自媒体" | "一个有技术背景、每周可投入 10 小时、无启动资金、目标在 6 个月内获得第一笔真实收入的人，当前高胜率路径" |

**条件分支必须落到一个明确推荐**。允许按目标/起点拆分支，但每个分支最终给出一条主路径，不是十个选项。

## 本仓库不是什么

- 不是道德说教——但**排除造假、违法、侵害他人、不可逆高风险行为**。否则它会退化成廉价成功学或灰产手册。
- 不默认所有路径等价；不把有支持者的传统路径和高胜率路径并列展示。
- 不把"长期成长""打好基础"自动视为正确答案。基础是否必要，取决于它是否是当前目标的瓶颈。
- 不以名人观点、传统共识、多数意见作为最终证据。
- 不是政治宣言。不围绕左翼/右翼/多元化等意识形态争论展开。核心是结果、条件、证据和执行。

## 核心立场

1. 不默认所有路径等价。
2. 不因为一种传统路径有人支持，就把它和高胜率路径并列展示。
3. 不把"长期成长""打好基础"当成自动正确的答案。
4. 基础学习是否必要，根据它是否构成当前目标的瓶颈判断。
5. 先做真实任务、再针对性补基础，往往可能比从底层完整学起更快——但必须写清适用条件。
6. 结果必须是真实结果，不是虚假指标。
7. 路径必须可以被验证、证伪和更新。
8. 不以名人观点、传统共识或多数意见作为最终证据。
9. 个人经验可以成为候选路径，但不能未经检验直接升级为客观规律。
10. 不把短期拿结果和长期能力建设当成同一件事；两者分别标记。

## Hack 的定义

这里的 Hack 不是违法、欺骗、造假、操纵或伤害他人。它是：

- 找到系统真正奖励什么
- 找到成果和机会的关键瓶颈
- 使用高杠杆工具
- 减少无意义前置学习
- 优先完成可以证明能力的真实产出
- 使用反馈快速修正路径
- 利用公开规则、信息差、传播和网络效应
- 在合法、真实的前提下缩短拿结果的路径

每条 Hack 是一个独立 Markdown 文件，带 YAML Front Matter，同时支持人类阅读和 AI 读取。完整结构见 [hack-template.md](hack-template.md)。

## 证据等级

每条 Hack 必须标注证据强度，观点与事实必须分离：

| 等级 | 含义 |
|---|---|
| **A** | 多来源数据或高质量研究支持 |
| **B** | 大量可复现案例和一致经验支持 |
| **C** | 有限案例、专家经验或强逻辑推断 |
| **D** | 待验证假设 |

## 状态生命周期

每条 Hack 有一个状态，随证据积累而迁移：

```
draft → active → contested → archived
   ↘________________↗
```

- **draft**：候选路径，证据不足（C/D），明确标注待验证
- **active**：经过至少一轮真实反馈循环验证，证据 B 以上
- **contested**：出现可信反例或证据冲突，正在争论中
- **archived**：条件环境已失效，或被证伪，保留记录供参考

任何 Hack 都可以被反驳。反驳需要**证据和反例**，不靠观点和情绪。流程见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 质量标准（一条合格 Hack 的门槛）

1. 目标明确（可观察的结果，不是"变优秀"）
2. 条件明确（适合谁、不适合谁）
3. 路径明确（单一主推荐，不是选项菜单）
4. 能立刻执行（今天的下一步动作）
5. 有检查点（1 周/2 周/1 个月/3 个月）
6. 有失败信号（什么迹象说明该转向）
7. 有证据等级（A/B/C/D）
8. 有更新时间（版本化）
9. 可以被反驳和修订
10. 不用空泛表达
11. 不只说"努力、坚持、打基础、建立人脉"——必须具体到努力什么、坚持多久、联系谁、产出什么、用什么指标判断
12. 不为了显得全面而塞入大量低价值信息
13. 不把单个成功者的事后故事直接当成普遍规律
14. 明确区分短期拿结果与长期能力建设

## AI 如何使用本仓库

AI 不是在这里回答问题，而是执行一套操作流程：明确结果 → 收集最少必要上下文 → 判定条件分支 → 检索对应 Hack → 给出单一主路径 → 给出立刻动作 → 设置检查点与失败信号 → 根据反馈切换分支或更新路径。完整流程见 [docs/ai-workflow.md](docs/ai-workflow.md)。
