# Build in Public：把真实产出公开转化为机会

## 1. recommended_path

核心逻辑：**机会分配发生在信息不对称的地方——你做出了一件事，但目标方不知道。公开输出是把"做出来了"这个信号传达到机会方的最高杠杆手段，且具有网络效应（公开吸引的反馈本身改善产出）。**

**0.2.0 校准：文献把这条路径劈成两层——"可见性与入站接触"有坚实证据，"转化为付费/正式机会"只集中在尾部、整体未被证实。** 本路径诚实标注这一落差（见 evidence 1.3 与 3.x）：你公开输出，最可靠的是被看见、被接触；能不能变成 offer/客户，取决于产出质量和尾部运气，不能把两者混为一谈。这恰恰是"成果在前"原则的文献依据——Marlow 的雇主访谈显示，雇主折扣低努力信号（fork、存在感）而奖励可验证的贡献深度。

主路径五条原则：

1. **成果在前，公开在后**：顺序永远不能倒。公开的是真实产出的过程和结果，不是"我打算做"。
2. **平台选择 = 目标机会实际存在的平台**：目标方在哪里，就在哪里公开。技术信号在 GitHub 被招聘方/研究者检索；中文圈机会在小红书/知乎；英文技术圈在 X；深度长文在公众号/博客。招聘筛选数据：LinkedIn 是被筛最频繁的平台（93-96%），X 最少被筛（17-29%，evidence 4.x）——**"在 X 上发帖求被看见"对求职者不是主渠道**。不是"哪个平台火选哪个"，是"我的机会方在哪个平台"。
3. **输出内容 = 真实产物 + 过程 + 可复用判断**：发布代码/数据/结果、记录踩坑与决策、给出别人能用的结论。情绪和纯观点内容产出的是流量，不是机会。
4. **频率取可持续值**：每周 1-2 条产出型更新，比爆发式更新 10 条然后消失强。持续性本身就是信号。
5. **公开内容必须导向转化**：每条公开内容回答"看到这条的人，如何找到我、如何与我合作"。没有转化路径的公开是自嗨。

**转化机制**（公开如何变成机会，按证据强度分层）：
- **机制 A（证据坚实，B+）— 搜索可见性与入站接触**：招聘方/导师搜索你的名字和领域词时能看到你；GitHub OSS 调查显示半数贡献者称 OSS 工作对当前岗位重要；招聘平台数据（HackerRank 2018）84.1% 招聘者看 portfolio。职业发展平台 CareerBuilder 数据：57% 的雇主不会面试"网上找不到"的候选人——**不被发现本身就是减分项**。
- **机制 B（证据中等，B）— 社交证明**：公开的可验证产出被当作能力证据；雇主访谈确认 GitHub 信号有效但只看"贡献深度"不看存在感。
- **机制 C（证据薄弱，C/D）— 入站转化（offer/客户）**：无大规模研究证实"公开 → 面试/客户"的直接转化；唯一的硬性结果检验（Bitzer 2017 工资溢价研究）发现**无工资溢价**——70% 的贡献者相信 OSS 帮助职业，但实测为零。
- **机制 D（证据中等，B）— 反馈循环**：公开吸引反馈，反馈改善产出。博客作者调查：93% 报告学习/记忆收益，52% 的帖子获得评论。

**诚实分层结论**：把公开当作"让机会方看见你"的机制（机制 A/B），而不是"直接换 offer"的机制（机制 C）。机制 C 的期望值依赖尾部运气，不可作为主策略。

## 2. immediate_next_action

今天：

1. 写下目标机会方清单：**"我的机会方是 X（导师/招聘方/客户/投资人），他们最常看 Y 平台"**——一句话锁定平台。
2. 发布第一条真实产出：把你已有的最新产出物（哪怕是不完美的 v0.1）公开，配一段 3-5 句的"做了什么、卡在哪、下一步"。

## 3. step_by_step_actions

```
阶段 1（第 1-2 周）：定位与基础设施
1. 写清目标机会方 + 平台（见 immediate_next_action）
2. 建立公开阵地：GitHub 仓库主页 / 平台账号，头像简介写明"我在做什么、找什么"
3. 发布第一条真实产出，开始第一篇"过程记录"
   - 产出物：可被检索的公开阵地 + 第一条产出

阶段 2（第 3-8 周）：建立可持续节奏
1. 每周 1-2 条产出型更新（新结果/新决策/新坑）
2. 每条更新末尾带转化路径（联系方式/仓库链接/合作意向）
3. 回复所有真实评论和私信（反馈是资产）
   - 产出物：连续 6 周更新记录

阶段 3（第 2-4 个月）：放大与定向
1. 复盘数据：哪些内容带来真实接触，哪些只有流量（用"真实对话数"衡量，不是阅读量）
2. 把高转化内容类型放大（做系列/深挖）
3. 主动定向：把最好的产出直接发给目标机会方（带链接，不是群发）
   - 产出物：≥1 次主动定向接触 + 内容类型复盘

阶段 4（第 4-12 个月）：转化与维护
1. 把入站机会转化为真实结果（合作/面试/客户）——注意：这是尾部事件，3-12 个月内不转化是常态，不是失败信号（见 failure_signals 区分）
2. 维持节奏，把"已转化"的案例再公开（形成飞轮）
3. 每季度检查：公开投入 vs 机会产出，调整平台和内容类型
   - 产出物：≥1 个可验证的机会转化（或诚实的"零转化但可见性已建立"复盘）
```

## 4. checkpoints

| 时间点 | 检查内容 | 通过标准 | 未通过的处理 |
|---|---|---|---|
| 第 2 周 | 阵地是否建立 | 第一条产出已公开，简介有转化路径 | 先完成最小公开动作 |
| 第 6 周 | 节奏是否建立 | 连续 4 周每周 ≥1 条产出型更新 | 检查是产出不足还是节奏设计问题 |
| 第 3 个月 | 是否有外部信号 | ≥1 次真实外部接触（评论/私信/合作邀约） | 换平台/换内容类型（见 pivot） |
| 第 6 个月 | 是否有转化动作 | 出现可推进的机会对话 | 检查转化路径是否清晰，主动定向 |
| 第 12 个月 | 是否有真实转化 | ≥1 个可验证机会落地 | 复盘：产出质量？平台错配？转化路径缺失？还是纯尾部运气问题 |

## 5. success_metrics

- 第 6 周：连续 6 周产出型更新
- 第 3 个月：≥1 次真实外部接触（不是点赞，是对话/邀约）
- 第 6 个月：≥1 次可推进的机会对话（面试/合作洽谈/客户咨询）
- 第 12 个月：≥1 个可验证机会落地（offer、合作、付费、资助）——**注意：文献显示这是尾部事件，未达成不自动等于路径失败；应结合可见性指标（被搜索到、被接触）综合判断**

## 6. failure_signals

- 3 个月零真实外部接触——平台错配或内容类型错配（纯流量 ≠ 机会）
- 阅读量高但零对话——内容是"表演型"而非"产出型"，或缺少转化路径
- 更新频率全靠意志力维持，产出没有真实进展——公开开始替代产出，立即回到成果
- 把时间主要花在排版、剪辑、互动技巧上——边际收益递减，核心仍是产出
- 收到负面反馈即停止——如果负面反馈指向真实缺陷，那是资产不是失败信号（但若是指向红线问题，立即处理）
- **可验证产出持续 6 个月但零外部接触**——强烈提示平台错配或机会方根本不在此渠道（见 pivot）
- 产出型更新占比持续低于 50%（大量观点/情绪内容）——退化为内容表演

## 7. pivot_rules

| 触发条件 | 转向动作 | 新分支 |
|---|---|---|
| 3 个月零外部接触 | 换平台（机会方可能在别处）或换内容类型（过程型 → 成果型） | 渠道调整，路径不变 |
| 高流量零转化 | 重写转化路径（简介/置顶/定向发送） | 转化修复 |
| 公开占用时间 > 产出时间 | 把公开频率降到可维持水平（每周 1 条） | 节奏调整 |
| 产出的核心部分无法公开（保密约束） | 转向公开"方法论/过程"而非"成果细节" | 脱敏公开 |
| 目标机会方变化（如从找工作到创业） | 平台和内容类型同步切换 | 分支切换 |
| 12 个月零转化但可见性已建立（被搜索/被接触） | 判断是尾部运气还是产品/产出质量问题；若是产出质量，回到产出本身而非加大公开 | 质量转向 |

## 8. disqualifying_conditions

- **无真实产出**：公开没有产出 = 内容表演。表演吸引的是流量和虚假认可，机会方识别成本极低。这不是本路径，这是消耗。
- **核心产出完全无法公开**：如果产出的任何实质部分都受保密约束，本路径的杠杆消失，应转向私域或"脱敏方法论"路线。
- **公开存在不可逆高风险**：未发表研究泄密可能直接毁掉成果价值；隐私或安全问题不可逆。不能设计规避方案时，禁止公开。
- **机会方完全不在公开平台**：若机会全靠内推/私下渠道，本路径杠杆大幅下降——可做但优先级低，不应挤占主渠道时间。

## 9. common_traps

- **成果/公开顺序颠倒**：先做人设再补产出——这是最常见死法。机会方最终看的是可验证产出。
- **平台迷信**：追"火"的平台，而不是机会方在的平台。招聘数据：X 是最少被筛的平台（17-29%），LinkedIn 最多（93-96%）——"发帖求被看见"要发对地方。
- **频率焦虑**：一天 5 条撑一周，然后消失三个月。持续性信号 > 爆发信号。
- **流量冒充机会**：点赞收藏 ≠ 机会。用"真实对话数/转化数"衡量，不用阅读量。
- **只发结果不发过程**：最终成果一条龙发布，错过整个反馈循环（过程中的迭代才是 build in public 的资产）。
- **公开未完成研究的核心结果**：投稿前泄露核心贡献可能致命。规则：公开过程和方法，核心结果按投稿节奏释放。
- **把机制 C 当主策略**：期望"公开直接换 offer/客户"——文献显示这是尾部事件（Bitzer 无工资溢价；creator 收入呈幂律）。把公开当"被看见"的机制，不是"被雇佣"的机制。

## 10. why_this_works

- **搜索可见性（证据坚实）**：招聘方、导师、客户会搜索领域关键词 + 你的名字。公开产出让你在搜索时"存在"。GitHub OSS 调查：半数贡献者称 OSS 工作对当前岗位重要；HackerRank：84.1% 招聘者看 portfolio；CareerBuilder：57% 雇主不面试网上找不到的人。
- **信号的真实性**：在信息不对称环境中，公开的可验证产出是最强信号——比自述和简历可信，因为可被任何人检验。雇主访谈（Marlow）确认：可验证的贡献深度（被接受的 commit、项目所有权）是有效信号，fork/存在感被折扣。
- **网络效应**：公开吸引反馈，反馈改善产出，改善后的产出再公开——形成自我加速循环。闭门造车没有这个循环。博客作者调查：93% 报告学习收益。
- **异步网络**：一次公开产出可以被反复检索、转发，边际传播成本趋近于零，而机会到达是异步的（可能 3 个月后有人看到）。
- **选择性注意力**：真实产出的公开会吸引高度相关的注意力（看懂的人、需要的人），流量质量远高于泛流量。

## 11. evidence

### 机制 A/B（可见性、入站接触、社交证明）——支持证据

- [B] **GitHub Open Source Survey 2017**（N≈5,500，公开数据）："半数贡献者称 OSS 工作对当前岗位有些/非常重要"；70% 就业；65% 的贡献是工作职责的一部分。https://opensourcesurvey.org/2017/
- [B] **Marlow & Dabbish 2013, CSCW**（7 雇主 + 7 求职者访谈）：所有 7 位雇主认为 GitHub 档案比简历更可靠地反映能力；使用的信号是贡献深度（被接受的 commit 到知名项目、项目所有权、side projects）；**fork/存在感被明确折扣**。https://www.cs.cmu.edu/~xia/resources/Documents/Marlow-cscw13.pdf
- [B] **HackerRank 2018 Developer Skills Report**（39,000+ 开发者/招聘者调查）：招聘时 84.1% 看 portfolio（通常 GitHub）、71% 看经验、仅 35.4% 看教育。https://www.prnewswire.com/news-releases/hackerrank-survey-of-more-than-39000-developers-finds-technical-hiring-managers-struggle-to-assess-skill-300586382.html
- [B] **Linux Foundation Open Source Jobs Report 2021**（>200 招聘经理 + >750 组织）：44% 的招聘经理认为 OSS 贡献经验是最重要的技能/经验。https://www.linuxfoundation.org/hubfs/LF%20Research/Open%20Source%20Jobs%20Report%202021%20-%20Report.pdf
- [B] **CareerBuilder 2017 雇主调查**（数千雇主）：70% 用社交媒体筛候选人；57% 不太可能面试网上找不到的候选人；25% 更可能跟进有强在线存在的候选人。https://resources.careerbuilder.com/employer-blog/employers-research-candidate-social-media-profiles
- [B] **El-Komboz & Goldbeck 2025, Labour Economics**（22,900 GitHub 开发者，DiD）：求职期 OSS 活动提升约 16%——人们**行为上相信**公开信号有效（信念证据）。https://ideas.repec.org/a/eee/labeco/v97y2025ics0927537125001241.html
- [B] **Xu, Nian & Cabral 2020, Management Science**（1,301 用户，1,520 次跳槽）：跳槽后声誉型活动下降 23.7%——公开贡献由职业动机驱动。https://pubsonline.informs.org/doi/10.1287/mnsc.2018.3264

### 机制 C（转化为正式机会）——反证与边界

- [B] **Bitzer, Geishecker & Schröder 2017, Applied Economics（核心反例）**："约 70% 的 OSS 贡献者相信 OSS 参与有益职业，但我们未发现 OSS 参与的实际劳动力市场溢价"——信念与结果的落差，全路径最重要的诚实边界。https://ideas.repec.org/a/taf/applec/v49y2017i14p1379-1394.html
- [B] **creator 收入分布（幂律）**：CreatorIQ 2026（N=5,095）：67% 年收入 <$10k，<5% 超 $100k，top 10% 拿走 62% 的平台支付。https://www.creatoriq.com/whitepaper/state-of-creators
- [B] **注意力集中（Pew）**：Twitter 用户 top 10% 产出 80% 的推文；top 25% 产出 97%；即便超高活跃用户，其帖子月均仅 37 个赞 + 1 个转发——**"发帖就有注意力"是错误的**。https://www.pewresearch.org/internet/2019/04/24/sizing-up-twitter-users/
- [C] **Substack 收入分布**：约 17,000 作者有付费收入；中位数年收入约 $4,000；top 10 作者合计约 $40M/年——幂律的极端版。https://backlinko.com/substack-users
- [D] **内容表演不转化的反面案例**：Indie Hackers 一手案例——80+ 人验证、连续 6 个月 #buildinpublic 日更，最终 43 个注册、2 个付费、$18 MRR；作者结论"BIP 制造虚假的验证感，围观者的鼓励不等于产品市场匹配"。https://www.indiehackers.com/post/i-validated-my-idea-with-almost-80-people-built-in-public-for-6-months-and-still-failed-spectacularly-6382ec2034

### 平台选择证据（机制 A 的分层）

- [B] **SHRM 2015**：43% 用社交媒体筛选；筛选中 LinkedIn 93%、Facebook 63%、X/专业网站 29%。https://www.shrm.org/in/topics-tools/news/talent-acquisition/hr-weeds-applicants-public-social-searches
- [B] **Tilburg University 2023**（NL，学术）：>25% 组织筛社交媒体；其中 LinkedIn 96%、Facebook 71%、Instagram 41%、X 17%。https://www.tilburguniversity.edu/current/news/more-news/quarter-organizations-screen-applicants-social-media
- [B] **Jobvite Recruiter Nation 2020**：LinkedIn 72%（2017 年为 92%，持续下降）；Instagram 18%→37%。https://web.jobvite.com/rs/328-BQS-080/images/2022-12-2020RecruiterNationSurvey.pdf

## 12. known_counterexamples

- **Bitzer et al. 2017（最重要的反例）**：OSS 贡献无工资溢价——"公开工作 → 收入提升"的因果链没有通过唯一一次硬性检验。本路径因此把机制 C 从主策略降级为尾部事件。
- **Creator 收入幂律**：67% 内容创作者年收入 <$10k（CreatorIQ 2026）；Substack 中位年收入 $4,000——以内容/公开为主业的经济回报是极端偏态的。
- **"学习 in public 却零转化"**：大量公开账号产出大量内容却零机会——原因是内容无真实产出支撑（表演型公开）。"成果在前"原则直接针对此反例。
- **Indie Hackers $18 MRR 案例**：6 个月日更 BIP，43 注册、2 付费、$18 MRR——公开吸引了关注，但没有市场匹配。公开 ≠ 商业验证。
- **部分雇主明确不通过公开渠道发现人才**：特定实验室/公司依赖内推——本路径不否认这类机会方的存在，但这类占比在下降，且公开产出不阻碍私域接触。
- **公开产出被抄袭/抢先**：存在公开后被抢先发表/抄袭的案例——对策：时间戳（GitHub commit 记录）、投稿节奏控制、敏感部分脱敏。

## 13. risks

- **失败概率**：中等偏高（若以"转化为正式机会"为唯一标准）；低（若以"建立可见性"为标准）。多数执行者死于"表演型公开"或"3 个月零反馈即放弃"。
- **时间成本**：公开输出每周 2-5 小时，若产出质量不变，这是纯增量成本。上限 = 每周投入。
- **声誉风险**：公开的失败记录可能被误解；过度包装会被社区识别。对策：只公开真实进展，主动标注不确定性。
- **知识产权/保密风险**：未发表研究、客户数据、商业机密的泄露不可逆。对策：脱敏规则（见 pivot）。
- **心理风险**：公开暴露增加压力；负面反馈可能打击执行。对策：把反馈当数据，不当评价。
- **长期能力风险**：若公开挤压真实产出时间，长期能力受损——用"公开时间 < 产出时间"硬约束。
- **期望管理风险（0.2.0 新增）**：若把"公开 = offer"当预期，12 个月零转化会摧毁执行。本路径明确：机制 A/B（被看见、被接触）是主收益，机制 C（转化）是尾部事件。
